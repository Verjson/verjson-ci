# GitLab mirror module

This module creates the internal project that hosts mirrored `verjson-ci` release tags. It provisions a dedicated push-enabled SSH deploy key, denies tag creation to every role, and authorizes only that deploy key to create protected tags. Supply the GitLab provider outside the module; keep its administrative token in the provider's supported environment variable, never Terraform variables or state. Project Owners and instance administrators remain inside the trust boundary because they can change tag-protection policy or delete tags.

Pass the public half of a dedicated SSH key as `mirror_deploy_key_public_key`; store its private half in a protected and masked CI file variable. Run `node tools/mirror/sync.mjs --source https://github.com/Verjson/verjson-ci.git --destination ssh://git@<gitlab-host>/<namespace>/verjson-ci.git` only from a protected scheduled pipeline/ref. Rotate the key on a fixed schedule and when runner access changes, and monitor deploy-key and protected-tag audit events. HTTPS remotes may use a runtime credential helper, but secrets must never appear in a remote URL. The synchronizer rejects local, file, remote-helper, scp-style, credential-bearing, and non-HTTPS/SSH remotes.

The tool synchronizes only strict, unprefixed SemVer tags. It fetches and validates every planned tag object before performing one atomic push, refuses to change an existing destination tag, and aborts without pushing if a source tag moves during synchronization. Tag-object equality assumes both repositories use the same Git object format. Synchronization is eventually consistent; release automation must wait for and record successful mirror completion before advertising the internal component version.

Adopter root modules must commit the `.terraform.lock.hcl` produced for their supported runner platforms. This repository tests Terraform 1.16.1 with `gitlabhq/gitlab` 19.3.x and bounds the provider to that compatible major series; update the constraint and lock file together after provider review.
