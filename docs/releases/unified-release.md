# Unified release protocol

`Unified release` is the sole release entrypoint. It is manually dispatched with an unprefixed SemVer and the exact protected `main` head. A read-only job validates that identity and tests the candidate without an environment or persisted checkout credential. The separately approved `verjson-ci-release` job receives `contents`, `packages`, and `id-token` permissions, checks out trusted `main` code with `persist-credentials: false`, and revalidates the commit before executing it. A merge or push to `main` never derives or publishes a version.

The release manifest binds one commit and version to the CLI archive integrity, OCI digest, schema, GitHub Action and reusable workflow, GitLab component, mirror kit, and independently signed GitHub and GitLab conformance receipts. `release/manifest.schema.json` is closed to unknown properties and is enforced when a manifest is built, restored, signed, or verified. Semantic checks additionally require both receipt request IDs and normalized result digests to match.

Receipt verification happens over canonical receipt bytes before manifest construction. Verification uses checked-in exact issuer and workload identity policies; the resulting manifest records the verified identity and receipt bundle digest rather than accepting identity claims from the receipt. A request ID, commit, image digest, issuer, identity, signature, or content mismatch terminates staging.

Release state is an append-only, signed and hash-chained transition ledger. Reservation is create-only and binds a version to one commit, a stable signer identity, and a random anchor before build work. Each transition carries a monotonic sequence, previous state, previous-record digest, manifest digest where applicable, and a signature. A separately persisted head makes valid-prefix truncation fail closed. Restore verifies the head, hash chain, every signature, transition edge, manifest schema, digest, version, commit, and signer identity before honoring even a `complete` state. Compare-and-swap append prevents concurrent dispatches from advancing the same reservation.

Publication is reconciled against a manifest-bound closed plan containing exactly CLI, OCI, GitHub Action, GitLab component, GitLab mirror, immutable release tag, GitHub consumption, and GitLab consumption endpoints. Missing, duplicate, unknown, or mismatched endpoints fail closed. The orchestrator re-reads every endpoint even when its ledger entry already exists, accepts only an exact digest, creates only when both endpoint and ledger entry are absent, and appends that endpoint receipt before advancing. A mismatch or disappeared artifact is terminal; it is never overwritten. Failures append a signed quarantine record containing phase, reason, and retry classification. Only an explicitly retryable quarantine may resume, and its history remains intact. If failure and quarantine persistence both fail, both errors are preserved.

The non-public path builds the real version-bound CLI archive and OCI image, materializes disposable GitHub, GitLab, mirror, tag, and consumption endpoints, deliberately interrupts after partial publication, and resumes through the durable ledger. It does not mutate a forge or require a license. The workflow keylessly signs and verifies the resulting manifest using the exact trusted release-workflow identity. Unit integration tests additionally cover incomplete plans, endpoint disappearance, conflicting content, concurrent reservation, and suffix truncation.

Issue #4 remains the only gate to the first public release. Until a license is selected, a non-dry-run dispatch fails before any tag or publication. Dry runs remain available so legal policy does not block release engineering verification.
