# Unified release protocol

`Unified release` is the sole release entrypoint. It is manually dispatched with an unprefixed SemVer and the exact protected `main` head. A read-only job validates that identity and tests the candidate without an environment or persisted checkout credential. The separately approved `verjson-ci-release` job receives `contents`, `packages`, and `id-token` permissions, checks out trusted `main` code with `persist-credentials: false`, and revalidates the commit before executing it. A merge or push to `main` never derives or publishes a version.

The release manifest binds one commit and version to the CLI archive integrity, OCI digest, schema, GitHub Action and reusable workflow, GitLab component, mirror kit, and independently signed GitHub and GitLab conformance receipts. `release/manifest.schema.json` is closed to unknown properties and is enforced when a manifest is built, restored, signed, or verified. Semantic checks additionally require both receipt request IDs and normalized result digests to match.

Receipt verification happens over canonical receipt bytes before manifest construction. Verification uses checked-in exact issuer and workload identity policies; the resulting manifest records the verified identity and receipt bundle digest rather than accepting identity claims from the receipt. A request ID, commit, image digest, issuer, identity, signature, or content mismatch terminates staging.

Release state is an append-only, signed and hash-chained transition ledger. Reservation is create-only and binds a version to one commit, a stable signer identity, and a random anchor before build work. Each transition carries a monotonic sequence, previous state, previous-record digest, manifest digest where applicable, and a signature. A checkpoint sequence in independently rooted monotonic storage anchors the current head. Restore detects a rolled-back local head even when its matching tail was deleted; it also safely completes a verified record interrupted immediately before or after local-head advancement. It verifies the external checkpoint, hash chain, every signature, transition edge, manifest schema, digest, version, commit, and signer identity before honoring any state. Compare-and-swap append prevents concurrent dispatches from advancing the same reservation.

Publication is reconciled against a manifest-bound closed plan containing exactly CLI, OCI, GitHub Action, GitLab component, GitLab mirror, immutable release tag, GitHub consumption, and GitLab consumption endpoints. Missing, duplicate, unknown, or mismatched endpoints fail closed. The orchestrator re-reads every endpoint even when its ledger entry already exists, including before returning an already-complete release. It accepts only an exact digest, creates only when both endpoint and ledger entry are absent, and appends that endpoint receipt before advancing. A mismatch or disappeared artifact is terminal; it is never overwritten. Failures append a signed quarantine record containing phase, reason, and retry classification. Only an explicitly retryable quarantine may resume, and its history remains intact. If failure and quarantine persistence both fail, both errors are preserved.

The non-public path builds and consumes the real version-bound CLI archive, pushes the OCI image to a disposable registry, and pins it by registry digest. It stages one immutable tag in a bare GitHub repository and synchronizes that tag without force into a separate bare GitLab mirror. A tag checkout invokes both the GitHub Action and reusable workflow through pinned `act`; a checkout of the mirrored tag invokes the GitLab component through a disposable GitLab CE runner. Separate fixture processes create separate signing keys and receipts. Consumption endpoint digests come from each independently observed normalized adapter result, never from receipt copies. The publisher requires both results before completion and can reconcile existing exact tags without rewriting them. The workflow keylessly signs and verifies an immutable snapshot of the resulting manifest using the exact trusted release-workflow identity.

Process-level recovery tests kill a worker immediately after an external endpoint is created but before its ledger append. A successor process opens the same durable ledger and independent checkpoint under the same stable signer identity, re-observes the exact endpoint, and completes without overwriting it. Separate tests hard-exit on both sides of head advancement and prove endpoint mismatch and checkpoint rollback fail closed.

Issue #4 remains the only gate to the first public release. Until a license is selected, a non-dry-run dispatch fails before any tag or publication. Dry runs remain available so legal policy does not block release engineering verification.
